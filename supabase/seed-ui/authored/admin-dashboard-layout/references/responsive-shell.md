# 后台外壳的响应式与可达性细则

本文补充 SKILL.md 里没展开的部分：断点策略的取舍、超宽屏留白分配、侧栏抽屉的可达性。

## 一、断点为什么是 1024 / 1280 / 1440

后台的断点和官网不同。官网断点跟内容排版走，后台断点跟**「能不能放下一个可用的表格」**走。

| 断点 | 判据 | 结论 |
| --- | --- | --- |
| 1024 | 侧栏 240 + 内容 784，表格只剩 5 列 | 必须收侧栏 |
| 1280 | 侧栏 240 + 内容 1040，表格可放 8 列 | 最低可用宽度 |
| 1440 | 侧栏 240 + 内容 1200，可开挤压式详情面板 | 可上 280 侧栏 + 64 顶栏 |
| 1920 | 内容 1680，两侧开始显得空 | 加留白到 32，别加内容宽度上限 |
| 2560 | 内容 2320，单行文本超过 1800 后阅读极难 | 正文区限 720，表格区不限 |

**不要**为了「响应式好看」在 1280 就把侧栏折成图标态。1280 是办公笔记本的主流分辨率，
用户在这个宽度下仍然需要看到完整菜单文字。

## 二、超宽屏（≥ 1920）怎么分配留白

很多人第一反应是给内容区加 `max-width`。这是错的：后台的表格、看板、监控图都需要横向空间。
正确的做法是**按区块分别限制**：

```css
.content { padding-inline: 24px; }          /* 容器不设上限 */
.form-page, .article-body { max-width: 720px; }  /* 只有正文/表单限宽 */
.table-page, .board-page { max-width: none; }    /* 表格/看板全宽 */
```

- 表单限 720px 的理由：单行中文超过约 90 字后，眼球回扫找下一行开始位置会明显变慢。
- 看板（kanban）在全宽下每列仍建议 280–320px，超出部分横向滚动，不要拉伸列宽 —— 拉伸后一列能看到的信息反而更少。
- 如果 2560 屏上表格列已经全部铺满还有余，把余量给主列（`1fr`），而不是均匀分给所有列。

## 三、侧栏抽屉（< 1024）的可达性

抽屉态是唯一「侧栏覆盖内容」的场景，规则比展开态更严：

1. **焦点陷阱**：抽屉打开时，`Tab` 循环限制在抽屉内；关闭后焦点回到触发按钮。
2. **滚动锁**：抽屉打开时给 `<body>` 加 `overflow: hidden`，关闭时移除。否则背景跟着滚，观感很差。
3. **遮罩**：`rgba(0,0,0,.4)`，点击关闭；遮罩本身不进 Tab 序列。
4. **Esc**：任何时候 `Esc` 关闭抽屉。
5. **`aria-expanded` / `aria-controls`** 挂在汉堡按钮上，`role="dialog"` + `aria-modal="true"` 挂在抽屉上。
6. **动画 200ms**，`transform: translateX(-100%)`，用 `prefers-reduced-motion` 时改为 0ms。

```css
@media (prefers-reduced-motion: reduce) {
  .sidebar, .sidebar-backdrop { transition: none; }
}
```

## 四、键盘导航的最低要求

后台重度用户 80% 的时间在用键盘。布局骨架必须保证：

- `Tab` 顺序：跳过按钮 → 侧栏 → 顶栏 → 内容区。侧栏不要放在 DOM 最前面再靠 CSS 挪位，那会让 Tab 顺序错乱。
- 侧栏菜单用 `<nav>` + `<ul>` + `<a>`，不要用一堆 `<div onclick>`。前者天然可聚焦、可被读屏识别。
- 展开/收起子菜单：`→` 展开、`←` 收起、`↑/↓` 在同一层移动、`Home/End` 到首尾。
- 焦点样式用 `:focus-visible`，`outline: 2px solid` + `outline-offset: 2px`，不要 `outline: none` 后不补替代样式。
- 顶栏高度 56 时，聚焦环不要被 `overflow: hidden` 裁掉，给容器留 2px padding。

## 五、对比度与长时使用

- 正文文字对背景对比度 ≥ 4.5:1（WCAG 2.2 AA）。后台常出现 `#999` on `#fff`（约 2.8:1），不达标。
- 次要文字（辅助说明、时间戳）最低 4.5:1，不要用 `#ccc`。
- 侧栏背景与内容区背景的明度差控制在 4%–8%：差太多像两个应用，差太少分不清边界。常用 `#f7f8fa`（侧栏）配 `#ffffff`（内容）。
- 长时间使用避免纯黑背景配纯白文字（对比度 21:1，反而刺眼）。深色后台用 `#0f1115` 背景 + `#e5e7eb` 文字。
