# 深色模式与 OLED

深色模式不是「把颜色取反」。取反的结果是：
**层级全部消失**（阴影看不见了）、**颜色全部过曝**（饱和色在暗底上发光）、
**文字太刺眼**（纯白配纯黑是 21:1，比浅色模式还极端）。

## 何时使用

- 从零实现一套深色主题
- 已有深色模式但用户反馈「看不清层级」「晚上看着累」「滚动有拖影」
- 要做 OLED 省电主题（纯黑底）
- 图片、插画、logo 在深色下显示不正常

## 核心规则

1. **大面积背景不要用 `#000000`，用 `#121212` 一档的深灰。**
   纯黑在 OLED 上的问题有三个：
   - **拖影（smearing）**：OLED 像素从「完全熄灭」到「点亮」的响应时间，
     比灰到灰的切换慢得多（尤其在低亮度下，蓝色子像素最慢）。
     滚动时浅色文字后面会拖一条暗影。
   - **光晕（halation）**：`#FFFFFF` 配 `#000000` 是 21:1 对比，
     在暗环境下高亮文字边缘会在视网膜上「晕开」，散光用户尤其明显。
   - **边界不可见**：`#000000` 和 `#121212` 的对比度只有 **1.12:1**，
     肉眼几乎分不出，导致所有分层都失效。

   `#121212` 到 `#1C1C1C` 是安全区。只有 OLED 省电场景（阅读器、时钟、待机屏）
   才值得用纯黑，且要提供开关。

2. **深色模式的分层对比度天然只有 1.1–1.7:1，永远达不到 WCAG 的 3:1。**
   这是数学限制：`#121212` 的相对亮度是 0.006，要达到 3:1 的相邻色需要
   亮度 0.118（约 `#626262`）—— 那已经是浅灰了，不叫深色模式。
   所以**深色模式的分层不能只靠色差**，必须配 1px 边框或顶部高光。
   审计时不能拿 1.4.11 去卡深色模式的卡片边界，但**必须**保证有边框之类的额外线索。

3. **灰阶分四层，每层差 6–10 个色阶（十六进制）。**

   | 层 | 色值区间 | 用途 |
   | --- | --- | --- |
   | L0 底层 | `#0A0A0A`–`#121212` | 页面背景 |
   | L1 卡片 | `#1A1A1A`–`#242424` | 卡片、列表项、输入框 |
   | L2 浮层 | `#262626`–`#333333` | 下拉菜单、Popover、Tooltip、Toast |
   | L3 最高层 | `#383838`–`#424242` | 对话框、底部抽屉、拖拽中的元素 |

   层与层之间至少差 8 个色阶（`#121212` → `#1A1A1A` 是 8），
   差 4 以内肉眼分不出来。

4. **深色下阴影必须被替换，不能只是「调深」。**
   阴影的原理是「比背景更暗」，但背景已经是 `#121212`，再暗就是纯黑，
   对比度不到 1.2:1，等于没有。替代方案按优先级：
   - **提高表面色**（tonal elevation）：浮层用 L2/L3 的灰，这是首选
   - **加 1px 边框**：`border: 1px solid rgba(255,255,255,0.10)`
   - **加顶部内高光**：`box-shadow: inset 0 1px 0 rgba(255,255,255,0.06)`
   - **外发光**（慎用）：`box-shadow: 0 0 0 1px rgba(255,255,255,0.08)`
   保留的阴影只作为「极弱的暗化」：`0 4px 12px rgba(0,0,0,0.5)`。

5. **正文不要用 `#FFFFFF`，用 `#E0E0E0`–`#EAEAEA`。**
   `#E6E6E6` 在 `#121212` 上是 **15.0:1**，`#FFFFFF` 是 **18.7:1**。
   15:1 已经远超 AAA 的 7:1，同时不会产生光晕。
   深色模式的正文对比度**目标区间是 7:1–12:1**，不是越高越好。

6. **高饱和颜色必须降饱和 + 提亮。**
   `#FF0000` 在 `#121212` 上会「发光」—— 高饱和度的红/蓝/紫在暗底上
   会因色差和亮度双重刺激显得刺眼。做法：
   - 饱和度降到原来的 **80–85%**
   - 亮度提到原来的 **110–120%**
   - 品牌色在浅色模式是 tone 40，深色模式用 tone 80（这正是 M3 的规则）
   反例：直接沿用浅色模式的品牌色，深色下按钮会像 LED 灯牌。

7. **模态遮罩（scrim）在深色模式下依然有效，但要不透明度更高。**
   浅色模式 `rgba(0,0,0,0.5)`；深色模式提到 `rgba(0,0,0,0.65)`–`0.75`。
   原因：底下的内容本身就是 `#121212`，暗化空间小。
   `0.65` 的遮罩叠在 `#1A1A1A` 上得到约 `#090909`，与 `#1A1A1A` 的对比度 1.5:1，
   刚好够区分。

8. **不要给照片和插画做反色。**
   照片反色会变成负片（人像变蓝、天空变橙），是明显的 bug。
   插画的处理方式见下文「怎么做」第 4 节。

## 怎么做

### 1. 完整的 token 表

```css
:root {
  color-scheme: light dark;   /* 让滚动条、表单控件、默认背景跟随系统 */
  --bg-base: #FFFFFF;
  --bg-card: #F7F7F8;
  --text-primary: #1A1A1A;
  --border-subtle: rgba(0, 0, 0, 0.08);
  --scrim: rgba(0, 0, 0, 0.50);
}

@media (prefers-color-scheme: dark) {
  :root {
    --bg-base: #121212;
    --bg-card: #1A1A1A;
    --text-primary: #E6E6E6;
    --border-subtle: rgba(255, 255, 255, 0.08);
    --scrim: rgba(0, 0, 0, 0.70);
  }
}
```

完整的成对 token（深色值都标了与背景的对比度）：

| Token | 浅色 | 深色 | 深色下对比度 |
| --- | --- | --- | --- |
| `--bg-base` | `#FFFFFF` | `#121212` | — |
| `--bg-card` | `#F7F7F8` | `#1A1A1A` | 1.12:1（需边框） |
| `--bg-overlay` | `#FFFFFF` | `#2A2A2A` | 1.34:1（需边框） |
| `--bg-dialog` | `#FFFFFF` | `#333333` | 1.65:1（需边框） |
| `--text-primary` | `#1A1A1A` | `#E6E6E6` | 15.0:1 |
| `--text-secondary` | `#5C5C5C` | `#A8A8A8` | 8.2:1 |
| `--text-disabled` | `rgba(0,0,0,.38)` | `rgba(255,255,255,.38)` | — |
| `--border-subtle` | `rgba(0,0,0,.08)` | `rgba(255,255,255,.08)` | — |
| `--border-strong` | `rgba(0,0,0,.16)` | `rgba(255,255,255,.16)` | — |
| `--scrim` | `rgba(0,0,0,.50)` | `rgba(0,0,0,.70)` | — |
| `--shadow-card` | `0 1px 3px rgba(0,0,0,.10), 0 4px 12px rgba(0,0,0,.06)` | `0 1px 2px rgba(0,0,0,.40)` | — |

`color-scheme: light dark` 这一行经常被忘掉。没有它，深色模式下：
原生滚动条还是白的、`<input type="date">` 的日历弹窗是白的、
`<select>` 的下拉是白的、首屏背景会闪一下白。

### 2. 深色下表达层级的标准写法

```css
.card {
  background: var(--bg-card);
  border-radius: 12px;
  box-shadow: var(--shadow-card);
  border: 1px solid var(--border-subtle);   /* 关键：用边框替代阴影的"边界"作用 */
}

.popover {
  background: var(--bg-overlay);
  border: 1px solid var(--border-strong);   /* 浮层边框更明显 */
  box-shadow:
    inset 0 1px 0 rgba(255, 255, 255, 0.06),  /* 顶部高光，模拟"光源在上" */
    0 8px 24px rgba(0, 0, 0, 0.60);           /* 保留，用于和下层拉开距离 */
}
```

对话框（L3）用 `--bg-dialog` 再叠一层遮罩，三层叠加后
`#121212` → `#333333` 的对比度是 **1.65:1**，虽然远低于 3:1，
但配合 1px 边框和遮罩，用户能明确感知层级。

### 3. 交互状态在深色下的取值

| 状态 | 浅色 | 深色 |
| --- | --- | --- |
| hover 叠层 | `rgba(0,0,0,0.04)` | `rgba(255,255,255,0.06)` |
| pressed 叠层 | `rgba(0,0,0,0.10)` | `rgba(255,255,255,0.10)` |
| focus 环 | `#1A73E8` | `#8AB4F8`（提亮，暗底上更清楚） |
| 选中项背景 | `rgba(26,115,232,0.10)` | `rgba(138,180,248,0.16)` |
| 分隔线 | `rgba(0,0,0,0.08)` | `rgba(255,255,255,0.08)` |
| 禁用文字 | `rgba(0,0,0,0.38)` | `rgba(255,255,255,0.38)` |

**注意方向**：浅色模式用「黑 + 低透明度」压暗，深色模式用「白 + 低透明度」提亮。
这是最容易搞反的一处 —— 深色下用黑色叠层会让元素越 hover 越暗，
看起来像被禁用了。

焦点环的颜色必须**单独提亮**。`#1A73E8` 在 `#121212` 上的对比度是 3.9:1，
勉强够；换成 `#8AB4F8` 能到 9.1:1，明显更清楚。

### 4. 图片与插画的处理

- **照片**：不反色。只做轻微降亮避免暗环境眩光：
  `filter: brightness(0.85) saturate(0.95)`。**不要低于 0.8**，会显得脏。
- **内联 SVG 图标**：一律用 `stroke="currentColor"` / `fill="currentColor"`，
  自动跟随文字色。
- **复杂插画**：准备两套资源，用 `<picture>` 配
  `<source media="(prefers-color-scheme: dark)">` 切换，不要靠 CSS 反色。
- **白底图片（logo、二维码、截图、图表）**：不反色，加一块浅色底板 ——
  `background: #FFFFFF; border-radius: 8px; padding: 12px;`。
  反色会让 logo 变负片、二维码扫不出来、图表颜色全错。
- **透明 PNG 上的黑色文字**：深色下会完全消失，必须换成 SVG + `currentColor`
  或加白底板。
- **表单控件**：`color-scheme: dark` 能让原生控件（滚动条、日期选择器、
  checkbox 默认样式）自动变深色，不要自己重写这些。

### 5. 过曝色（Vibrating Colors）

高饱和颜色在暗底上会产生「振动」感 —— 两种颜色的亮度接近但色相差很大时，
边缘看起来在抖动。典型组合：

| 组合 | 问题 |
| --- | --- |
| `#FF0000` on `#121212` | 红光溢出，刺眼 |
| `#0000FF` on `#121212` | 几乎看不见（亮度太低） |
| `#FFFF00` on `#121212` | 极刺眼 |

修正原则：**深色模式下的强调色统一「降饱和 + 提亮」**。
浅色模式的红用 `#D32F2F`，深色模式换成 `#FF8A80`。
如果用的是 M3 调板，规则是现成的：浅色取 tone 40，深色取 tone 80。
tone 80 的色值天然就是「提亮 + 相对降饱和」的。

### 6. 切换与持久化

```ts
type Theme = 'light' | 'dark' | 'system'

function applyTheme(t: Theme) {
  const dark = t === 'dark' ||
    (t === 'system' && matchMedia('(prefers-color-scheme: dark)').matches)
  document.documentElement.dataset.theme = dark ? 'dark' : 'light'
  // 同时更新 meta 的 theme-color，避免移动端地址栏颜色不匹配
  document.querySelector('meta[name="theme-color"]')
    ?.setAttribute('content', dark ? '#121212' : '#FFFFFF')
}

// 系统主题变化时也要跟随（用户可能在 App 打开时切了系统主题）
matchMedia('(prefers-color-scheme: dark)').addEventListener('change', () => {
  if (getStoredTheme() === 'system') applyTheme('system')
})
```

**首屏闪白**的处理：在 `<head>` 里同步执行一段内联脚本，
读 `localStorage.theme` 并立即设置 `document.documentElement.dataset.theme`，
不要等 React/Vue 挂载后才切换 —— 否则深色模式用户每次刷新都会看到一瞬白屏。

## 检查清单

- [ ] 页面背景是 `#0A0A0A`–`#1C1C1C`，不是 `#000000`（除非是 OLED 省电模式且有开关）
- [ ] 灰阶四层，相邻层差 ≥ 8 个色阶
- [ ] 每个卡片/浮层都有 1px 边框或顶部内高光（不只靠色差）
- [ ] 正文色是 `#E0E0E0`–`#EAEAEA`，不是纯白
- [ ] 正文对比度在 7:1–12:1 之间（不是越高越好）
- [ ] 强调色在深色下单独定义过（降饱和 + 提亮），不是沿用浅色值
- [ ] 焦点环颜色在深色下单独提亮，对比度 ≥ 3:1
- [ ] hover / pressed 叠层用白色低透明度，不是黑色
- [ ] 模态遮罩不透明度 ≥ 0.65
- [ ] 照片不反色，只做 `brightness(0.85)` 以内的降亮；白底图片有白色底板
- [ ] 内联 SVG 用 `currentColor`
- [ ] 声明了 `color-scheme: dark`，滚动条和原生控件是深色
- [ ] 首屏无白闪（head 里同步设置 `data-theme`）
- [ ] `<meta name="theme-color">` 跟随主题，系统主题切换时页面实时跟随
- [ ] 真机 OLED 上滚动一遍，确认无拖影
- [ ] 在 30% 亮度下看一遍，确认没有大面积高亮块刺眼

## 常见错误

| 错误做法 | 为什么错 | 正确做法 |
| --- | --- | --- |
| 背景用 `#000000` | OLED 上滚动有拖影，与卡片层对比只有 1.12:1，层级消失 | 用 `#121212` |
| 深色下只把阴影调黑 | 背景已经接近黑，阴影不可见，浮层和底层分不开 | 提高表面色 + 加边框 |
| 正文用 `#FFFFFF` | 21:1 对比，暗环境下光晕明显，长文阅读疲劳 | `#E6E6E6`（15:1） |
| 沿用浅色模式的品牌色 | 高饱和色在暗底上发光，像 LED 灯牌 | 降饱和 15–20% + 提亮 10–20% |
| hover 用 `rgba(0,0,0,0.1)` | 深色下越 hover 越暗，像被禁用 | `rgba(255,255,255,0.06)` |
| 给照片加 `filter: invert(1)` | 变负片，人像变蓝、天空变橙 | 不反色，最多 `brightness(0.85)` |
| 忘了 `color-scheme: dark` | 滚动条、日期选择器、下拉框全是白的 | 声明 `color-scheme` |
| 主题切换在框架挂载后执行 | 每次刷新闪一下白屏 | `<head>` 里同步脚本设置 |
| 深色模式用同一套阴影值 | 阴影不可见，浮层贴在下层上 | 深色单独定义阴影（更弱）+ 边框 |
| 白底 logo 直接反色 | 品牌色变负片，二维码扫不出来 | 加白色底板，不反色 |
| 对比度追求越高越好 | 21:1 比 4.5:1 更难受，光晕和疲劳 | 目标 7:1–12:1 |
