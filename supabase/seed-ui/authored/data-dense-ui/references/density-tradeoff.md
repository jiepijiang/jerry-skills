# 密度与可读性的取舍

「塞更多信息」和「看得清」是一对真实冲突。这份文件给的是**判据**，不是偏好。

## 一、先确定密度目标

| 场景 | 目标密度 | 判据 |
| --- | --- | --- |
| 监控大盘 / 值班大屏 | 极高 | 单屏 ≥ 25 行，颜色承担主要识别任务 |
| 日志检索 / 数据核对 | 高 | 单屏 ≥ 20 行，等宽字体 |
| 订单 / 工单管理 | 中高 | 单屏 15–18 行，行高 40px |
| CRM 客户列表 | 中 | 单屏 12–15 行，行高 40–44px |
| 内容审核（含缩略图） | 中低 | 单屏 8–10 行，行高 56–64px |

密度不是越高越好，而是**「一次判断所需的全部信息是否在一屏内」**。
如果一次判断需要对照 3 个字段，那这 3 个字段必须同屏，否则密度再高也是无效的。

## 二、字号与对比度的硬下限

无论多紧凑，以下数值不可突破：

| 项 | 下限 | 依据 |
| --- | --- | --- |
| 正文字号 | 12px | 低于 12px 中文笔画糊在一起 |
| 次要文字对比度 | 4.5:1 | WCAG 2.2 AA 正文要求 |
| 大字号（≥18.66px 粗体或 ≥24px）对比度 | 3:1 | WCAG 2.2 AA |
| 表格行与背景的区分 | 不明显于 1.2:1 的色差 | 行分隔需要可辨识 |
| 可点击图标热区 | 32×32px（桌面鼠标） | 小于此值误点率显著上升 |

**中文不要用 12px 以下**。11px 的英文数字勉强可读，但中文「警」「管」「繁」这类字会糊成一团黑点。
如果需要更紧凑，正确做法是**减少列**，不是缩小字号。

对比度示例：
- `#333` on `#fff` ≈ 12.6:1 ✅
- `#666` on `#fff` ≈ 5.7:1 ✅
- `#999` on `#fff` ≈ 2.8:1 ❌（不能用于正文，只能用于禁用态）
- `#666` on `#fafafa` ≈ 5.5:1 ✅

## 三、纵向空间从哪来

按性价比排序，优先砍上面的：

1. **页面标题行**（省 0–56px）：如果面包屑已经说明了位置，标题可以并进工具栏。
2. **过滤器展开行**（省 48px）：收进抽屉。
3. **行高**（省 8–16px/行）：从 48 降到 40，15 行省 120px。**但这是有代价的，放后面砍。**
4. **表头**（省 0px）：表头不能砍，它是理解数据的唯一线索。
5. **分页栏**（省 0px）：分页必须存在，且必须显示「共 N 条 / 每页 M 条」。
6. **字号**（不要砍）：见上节，12px 是底线。

常见误区：一上来就砍字号和行高。正确顺序是先把「不是数据本身」的东西挪走。

## 四、横向空间怎么用

宽屏上的横向空间优先给**新列**，而不是给**更宽的列**：

| 优先级 | 做法 |
| --- | --- |
| 1 | 增加用户需要的字段列（如「最后跟进时间」） |
| 2 | 主列从 200px 放宽到 320px，减少省略号 |
| 3 | 操作列从图标改成「图标 + 文字」 |
| 4 | 右侧常驻详情面板（≥1440 时） |
| 5 | 什么也不做，留白 —— 这比拉伸列好 |

最差的做法：让所有列按比例变宽。结果是每列都很宽但每列都没多出信息，
用户视线扫描距离还变长了。

## 五、颜色的密度作用

在紧凑表格里，颜色承担了很大一部分识别成本：

- 状态用**色点 + 文字**（`● 已完成`），不要只用颜色。
  只用颜色时色盲用户完全无法区分，且打印/截图后信息丢失。
- 色点直径 6px，与文字间距 6px，垂直居中。
- 状态色最多 5 种（成功/警告/失败/进行中/中性），超过 5 种用户记不住。
- 用色相区分状态，不要用同一色相的不同明度（`#52c41a` 与 `#95de64` 在紧凑行里无法区分）。

## 六、什么时候该「降低密度」

出现以下任一信号，说明当前密度已经过头：

1. 用户在测试中频繁点错行（> 5% 的点击落在相邻行）。
2. 需要放大浏览器才能看清（测试时出现 `Cmd +` 操作）。
3. 一屏内出现两处以上省略号（`...`），且都是关键字段。
4. 用户需要「导出到 Excel 看」—— 说明界面本身没能完成任务。
5. 行内文字与行分隔线在截图上无法分辨。

反过来，出现以下信号说明密度不足：

1. 单屏行数 < 10（排除内容审核类页面）。
2. 用户抱怨「翻页太多」。
3. 表格下方留白超过 200px 而分页显示「共 500 条」。

## 七、密度切换开关的实现

给用户一个开关，是解决争议最省事的办法：

```js
// 持久化
const density = localStorage.getItem('table-density') || 'default'
document.querySelector('[data-table]').dataset.density = density

// 切换时不要重新请求数据，只改 CSS 变量
// 注意：虚拟滚动的行高常量必须同步更新，否则滚动位置会错乱
```

实现细节：
- 开关位置放在工具栏最右侧，用图标（三条疏密不同的横线）而非下拉框。
- 切换后**保持滚动位置对应的数据行**，而不是保持像素位置。
- 虚拟滚动场景下，切换密度后必须重算 `ROW_H` 并重置滚动位置。

## 八、检查清单

- [ ] 单屏有效行数符合该场景的目标区间
- [ ] 正文字号 ≥ 12px，次要文字对比度 ≥ 4.5:1
- [ ] 状态区分不依赖颜色单独承载（有色点 + 文字）
- [ ] 横向空间优先用于增加列，而非拉宽已有列
- [ ] 纵向空间先从非数据区块里省，最后才动行高
- [ ] 提供密度切换并持久化，切换后不重新请求数据
- [ ] 虚拟滚动下行高常量随密度同步更新
- [ ] 截图上行分隔线清晰可辨
