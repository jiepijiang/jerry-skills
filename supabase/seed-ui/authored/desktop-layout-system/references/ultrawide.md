# 超宽屏（≥1920）与多栏布局细则

## 一、先算清楚你面对的是哪种超宽屏

| 分辨率 | 典型设备 | 浏览器有效宽度（约） | 备注 |
| --- | --- | --- | --- |
| 1920×1080 | 24" 1080p | 1900 | 100% 缩放 |
| 1920×1200 | 24" 16:10 | 1900 | 纵向多 120px |
| 2560×1440 | 27" 2K | 2540 | 100% 缩放下字号偏小，常配 125% |
| 2560×1440 @125% | 27" 2K 缩放 | 2032 | **实际最常见** |
| 3440×1440 | 34" 带鱼屏 | 3420 | 21:9，横向极宽纵向一般 |
| 3840×2160 @150% | 32" 4K 缩放 | 2560 | 逻辑宽度等同 2K |

关键结论：**因为 Windows 默认缩放，绝大多数用户的逻辑宽度落在 1900–2560 之间**。
3440 的带鱼屏是少数派，但一旦命中，横向留白问题最刺眼。

## 二、三种处理手法的具体数值

### 手法 ①：铺满 + 最小留白（数据型）

```css
.data-surface {
  padding-inline: 32px;      /* <1920 用 32，≥1920 提到 40 */
}
@media (min-width: 1920px) {
  .data-surface { padding-inline: 40px; }
}
```

适用：表格、看板、监控大盘、日志查询。
判断：页面的主体是「列」或「卡片网格」，多一列就有价值。

### 手法 ②：限宽居中（通用型）

```css
.page-shell {
  max-width: 1200px;
  margin-inline: auto;
  padding-inline: 32px;
}
```

适用：营销页、设置页、表单页、定价页。
判断：页面主体是「一段一段的纵向内容」，宽度增加不会增加信息量。

限宽值的选择：`1080 / 1200 / 1440` 三档之一。不要写 1300 这种数字 ——
和栅格（24 的倍数）除不尽，12 列布局会出现小数像素。

### 手法 ③：加侧栏 / 分栏（内容型）

```css
@media (min-width: 1536px) {
  .doc-layout {
    display: grid;
    grid-template-columns: 240px minmax(0, 720px) 200px;
    gap: 48px;
    justify-content: center;
    align-items: start;
  }
  .doc-layout > .toc  { position: sticky; top: 88px; }
  .doc-layout > .meta { position: sticky; top: 88px; }
}
```

适用：文档、长文、API 参考、帮助中心。
`justify-content: center` 让三列整体居中，而不是左对齐后右侧空一大块。

## 三、粘性侧栏的数值

```css
.sticky-aside {
  position: sticky;
  top: 88px;               /* 顶栏 64px + 24px 呼吸 */
  max-height: calc(100vh - 112px);  /* 88 + 底部 24 */
  overflow-y: auto;
  overscroll-behavior: contain;     /* 滚到底不把外层页面带着滚 */
}
```

- `top` 必须等于「吸顶导航高度 + 间距」，写成 `0` 会被吸顶栏盖住。
- `max-height` 必须设，否则目录比正文长时侧栏永远滚不到底。
- `overscroll-behavior: contain` 防止滚动链传递，这是粘性侧栏最容易被忽略的一行。

## 四、多栏的列宽分配

| 场景 | 列宽方案 |
| --- | --- |
| 文档（目录 + 正文 + 大纲） | `240px / minmax(0,720px) / 200px`，gap 48 |
| 后台（侧栏 + 主区） | 侧栏 `flex: 0 0 240px`，主区 `flex: 1 1 auto; min-width: 0` |
| 后台（侧栏 + 主区 + 详情面板） | `240 / minmax(0,1fr) / 360`，详情面板可关闭 |
| 看板（多列卡片） | `grid-template-columns: repeat(auto-fill, minmax(320px, 1fr))` |
| 编辑器（文件树 + 代码 + 预览） | `200 / minmax(0,1fr) / minmax(0,1fr)` |

统一原则：**除主内容区外，所有列的宽度都是固定的**。
让两个侧栏同时参与 `1fr` 分配，在 1920 上会出现侧栏比正文还宽的荒诞结果。

## 五、≥2560 时的额外检查

1. 卡片网格是否还只有 3 列？用 `auto-fill` + `minmax(320px,1fr)` 让它自然变成 4–5 列。
2. 表格列宽是 `%` 还是固定值？固定值在大屏上会留出巨大空隙，改用 `min-width` + 主列 `1fr`。
3. 模态框是否还是 `width: 600px`？超宽屏上小模态框会显得像悬浮的一张贴纸，
   可提到 `640px`，但**不要**跟随屏幕放大到 1200px —— 表单视线跨度过大。
4. 背景装饰图是否被拉伸变形？用 `background-size: cover` + 明确的 `aspect-ratio` 容器。
5. 有没有 `100vw` 的横向滚动条问题？`100vw` 包含滚动条宽度，
   应该用 `100%` 或 `width: 100vw; overflow-x: hidden` 配合。

## 六、带鱼屏（21:9）的专门处理

- 横向铺满后，一行的**视觉扫描距离**过长，表格应限制单行总宽或拆成两块。
- 三栏布局在 3440 上会变成「三块孤岛」，把中间主栏上限提到 960px 会更稳。
- 视频 / 图表容器注意 `aspect-ratio`，不要让 21:9 容器里塞 16:9 内容还铺满。

```css
.media-16x9 {
  aspect-ratio: 16 / 9;
  max-width: 1200px;   /* 防止带鱼屏上视频高到超出视口 */
  margin-inline: auto;
}
```

## 七、检查清单

- [ ] 在 1920 与 2560 下分别截图，两张图的**内容行数/列数**不同
- [ ] 数据型页面 2560 下单侧留白 < 100px
- [ ] 内容型页面正文宽度 ≤ 720px，且有 sticky 目录
- [ ] 粘性侧栏 `top` 值 = 吸顶栏高度 + 间距，未被遮挡
- [ ] 粘性侧栏滚动到边界时外层页面不跟着滚（`overscroll-behavior`）
- [ ] 多栏布局中只有主区使用 `1fr`，且带 `min-width: 0`
- [ ] 模态框宽度不随屏幕线性放大
- [ ] 带鱼屏下表格单行扫描距离可接受（可用横向滚动或固定首列缓解）
