# 金额输入、校验与风控流程

金额输入是金融产品里**出错代价最高**的一个输入框。
用户输错一位就是 10 倍差额。这一节讲怎么把输入和校验做到位。

## 一、金额输入框

### 键盘与格式

```html
<input id="amt" inputmode="decimal" autocomplete="off"
       aria-describedby="amt-hint amt-error" value="0.00">
```

- `inputmode="decimal"`：移动端唤起带小数点的数字键盘
  （`inputmode="numeric"` 在部分键盘上没有小数点，不要用）
- `autocomplete="off"`：金额不要被浏览器自动填充
- `type="text"` 而非 `type="number"`：`number` 类型会有滚轮误改、
  且无法显示千分位，也无法限制小数位数
- 输入时实时插入千分位，**但必须维护光标位置**：
  记录光标左侧的数字字符个数，格式化后重新定位。
  不处理光标的话，用户在中间插入一位会导致光标跳到末尾

### 格式化函数

```js
function formatAmount(raw) {
  // raw: 用户输入的原始串，只保留数字和小数点
  let s = raw.replace(/[^\d.]/g, "");
  const firstDot = s.indexOf(".");
  if (firstDot !== -1) {
    s = s.slice(0, firstDot + 1) + s.slice(firstDot + 1).replace(/\./g, "");
  }
  let [int, dec] = s.split(".");
  int = int.replace(/^0+(?=\d)/, "");       // 去掉前导 0，但保留单个 0
  int = int.replace(/\B(?=(\d{3})+(?!\d))/g, ",");
  if (dec !== undefined) dec = dec.slice(0, 2);   // 最多 2 位小数
  return dec !== undefined ? `${int}.${dec}` : int;
}
```

规则：

- 最多 2 位小数（人民币最小单位是分）
- 不允许前导 0（`007` → `7`）
- 空值不显示 `0.00`，显示 placeholder（`请输入金额`），
  否则用户需要先删除再输入
- 粘贴时也走同一函数（用户会粘贴 `1,299.00` 或 `1299.00`）

### 辅助元素

| 元素 | 位置 | 作用 |
| --- | --- | --- |
| `全部` 按钮 | 输入框右侧 | 一键填入可用余额 |
| 可用余额提示 | 输入框下方 12px | `可用余额 ¥58,420.00` |
| 快捷金额 | 输入框下方 | `100 / 500 / 1000`，热区 ≥ 44px |
| 大写金额 | 输入框下方（可选） | `壹万贰仟元整`，用于对公场景 |
| 手续费预估 | 输入框下方 | `手续费 ¥0.00，实际到账 ¥12,000.00` |

## 二、校验时机与文案

**不要在用户输入过程中标红**。分三级处理：

| 时机 | 处理 |
| --- | --- |
| 输入中 | 只做格式化，不报错；超限时按钮置灰 |
| 失焦（blur） | 校验格式（是否为空、是否 ≤ 0、是否超 2 位小数） |
| 点击下一步 | 全量校验，滚动并聚焦到第一个错误项 |

错误文案要**给出边界值**：

| 场景 | 差文案 | 好文案 |
| --- | --- | --- |
| 超余额 | 金额错误 | 超出可用余额，最多可转 ¥58,420.00 |
| 低于限额 | 金额过小 | 单笔最低 ¥1.00 |
| 超单笔限额 | 金额过大 | 单笔最高 ¥50,000.00，可分次转账 |
| 超日累计 | 金额错误 | 今日剩余额度 ¥12,300.00 |

**关键**：错误提示要写在**对应字段下方**，并用 `aria-describedby` 关联，
同时把 `aria-invalid="true"` 加到输入框上。

## 三、二次确认页

确认页的信息清单（缺一不可）：

```
收款方      李**（招商银行 ****1234）
转账金额    ¥12,000.00        ← 字号是输入页的 1.2 倍以上
手续费      ¥0.00
实际到账    ¥12,000.00
到账时间    预计 2 小时内
备注        货款
```

设计要点：

- 金额用**最大字号**，且单独占一行，不要和其他字段挤在一行
- 收款方只显示姓氏 + `**` 与账号后 4 位，**不显示完整账号**（隐私）
- 每一项都要有标签，不要只显示值
- 提供「修改」入口，点击回到输入页且**保留已填内容**
- 底部按钮：`确认转账 ¥12,000.00`（主）+ `取消`（次）
- **确认页禁止任何营销内容**（推荐产品、优惠券、广告位）

## 四、验证方式的选择

| 场景 | 验证方式 | 理由 |
| --- | --- | --- |
| 小额、常用收款人 | 点击确认即可 | 摩擦最小，风险可控 |
| 大额（阈值由业务定） | 支付密码 | 一次性验证，用户可接受 |
| 首次转给新收款人 | 支付密码 + 短信验证码 | 双重确认，防冒充 |
| 修改支付密码/绑定手机 | 原密码 + 新验证码 | 高危操作 |
| 生物识别可用时 | 指纹/面容优先 | 比输密码快，且不可被肩窥 |

规则：

- 验证码输入框用 `inputmode="numeric"` + `autocomplete="one-time-code"`，
  iOS/Android 可自动填充短信验证码
- 验证码倒计时 60 秒，重发按钮在倒计时中置灰并显示剩余秒数
- 验证失败后**不清空已填的转账信息**，只清空验证码
- 连续失败 3 次要给出账号锁定提示与解锁路径

## 五、结果页

成功：

```
✓ 转账成功
¥12,000.00
收款方 李**（招商银行 ****1234）
订单号 2026101200012345
到账时间 预计 2 小时内

[查看交易记录]  [完成]
```

- 金额是页面上最大的元素
- 订单号可长按复制
- 提供撤销入口（如业务支持）：`2 小时内可撤回`
- 「完成」按钮回到首页，「查看交易记录」进明细

失败：

- 明确说明**失败原因类别**：余额不足 / 风控拦截 / 收款方信息有误 / 网络异常
- 给出**重试路径**：网络类可直接重试；风控类需人工核实
- 保留订单号，便于客服查询
- 不要用「操作失败，请稍后重试」这种无信息量文案

## 六、风控拦截页

拦截页的三段结构：

1. **说明发生了什么**（不暴露规则细节）
   `为保护账户安全，本次交易需要人工核实。`
2. **给出具体下一步**
   - `拨打 400-XXX-XXXX 转 3 核实身份`
   - `前往「我的 → 安全中心」完成实名升级`
   - `等待 15 分钟后重试`
3. **保留订单**
   `订单号 2026101200012345（已保留 24 小时）`，
   并提供一个「核实后继续支付」的入口

**不要**做的事：

- 只显示错误码（`Error 4032`）
- 把拦截原因写得太具体（会被用来试探风控规则）
- 让用户重新填写全部信息
- 在拦截页放营销推荐

## 七、无障碍

- 金额输入框必须有关联 `<label>`，不要只用 placeholder
- 错误信息通过 `aria-describedby` 关联，并实时更新
- 验证码输入建议用**单字符分组输入**（6 个格子）时，
  仍要保留一个真实的 `<input>` 承载值，否则读屏无法工作
- 结果页的「成功/失败」用文字表达，不要只用一个图标颜色
- 所有可点元素热区 ≥ 44×44px
