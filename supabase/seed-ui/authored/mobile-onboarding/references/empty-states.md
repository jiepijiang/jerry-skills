# 空状态文案模板（五类）

「暂无数据」是设计债。用户在空状态里问的其实是三个问题：
**这是正常的吗？是我的问题吗？我现在该做什么？**
每一类空状态都要回答这三个问题，只是答案不同。

## 一、首次为空（First-run empty）

场景：用户刚注册/刚装上，一条数据都没有。

特点：用户**不知道这个功能是干嘛的**，需要教育。
这是唯一适合放插画和较长说明的空状态。

```
标题：还没有项目
说明：创建一个项目，把相关的任务和文件放在一起。
主按钮：创建项目
次级：了解项目是什么 →（打开帮助文档）
```

要点：
- 主按钮必须是**创建动作本身**，不是「去首页」「返回」
- 说明里要点出这个功能的核心价值（「放在一起」= 组织能力）
- 次级链接是可选的，给愿意深究的用户

反例：
```
暂无项目
[ 刷新 ]
```
「刷新」对首次用户毫无意义 —— 他没有数据可刷。

## 二、用户清空（User-cleared empty）

场景：用户主动删光了所有内容，或完成了所有待办。

特点：这是**用户自己造成的**，而且可能是好事（待办清空 = 成就感）。
绝对不要用「暂无数据」这种像报错的说法。

```
（待办清空时）
标题：今天的事都完成了
说明：明天见。
（无按钮，或一个很轻的「看看已完成」）

（用户主动删光时）
标题：回收站是空的
说明：删除的内容会在这里保留 30 天。
主按钮：返回上一页
```

要点：
- 待办清空、打卡完成、收件箱清空这类场景，文案要有**正向反馈**
- 删除类清空，说明要讲清「多久内可以恢复」，降低焦虑
- 这一类的插画可以用得比首启更活泼（完成态）

## 三、搜索/筛选无结果（No results）

场景：有数据，但当前条件下匹配不到。

特点：用户**有一个明确的目标没达成**，需要的是「怎么改条件」，不是「去创建」。
最典型的错误是给「新建」按钮 —— 用户明明是在找东西。

```
标题：没有找到「会议纪要」
说明：试试更短的关键词，或检查是否有错别字。
主按钮：清除筛选
次级：搜索全部内容
```

要点：
- 标题里**回显用户的搜索词**，让他确认搜对了
- 说明给具体的修正方向（更短的关键词、检查错别字、换分类）
- 主按钮是「清除筛选条件」而不是「新建」
- 如果有拼写纠错能力，直接给「你是不是想找：会议记录」

## 四、出错（Error empty）

场景：请求失败、超时、服务端 5xx。

特点：**不是用户的错**，所以文案不能有责备感，且必须给重试路径。

```
标题：加载失败
说明：网络好像不太稳定，请稍后重试。
主按钮：重新加载
```

要点：
- 标题用「加载失败」而不是「出错了」—— 后者太笼统
- 说明要**区分错误类型**：
  - 网络断开 → 「当前无网络连接」
  - 超时 → 「网络较慢，请稍后重试」
  - 5xx → 「服务暂时不可用，我们正在修复」
  - 4xx（参数错）→ 这种情况不该让用户看到，应上报并回落
- 不要显示错误码给普通用户，但要在长按或日志里能拿到
- **不要**自动无限重试，用户会看到页面反复闪

## 五、无权限 / 无访问权（Permission empty）

场景：未登录、权限不足、内容已删除、账号被限制。

特点：用户**看不到内容是因为权限**，需要的是「怎么获得权限」。

```
（未登录）
标题：登录后查看收藏
说明：你的收藏会同步到所有设备。
主按钮：登录

（内容已删除）
标题：内容已被删除
说明：作者已删除这条内容。
主按钮：返回

（无访问权）
标题：仅成员可见
说明：向管理员申请加入即可查看。
主按钮：申请加入
```

要点：
- 「未登录」场景里，说明要讲**登录的好处**（同步、跨设备），不是「请先登录」
- 「已删除」不要给重试按钮，重试一万次也还是删了
- 权限类空状态**不要**显示搜索框或筛选器，用户没有东西可筛

## 视觉规格

| 元素 | 规格 |
| --- | --- |
| 容器 | 内容区垂直居中（不是整屏居中，要避开导航栏和 Tab bar） |
| 插画 / 图标 | 120–200pt，单色或双色，透明度 100%（不要用 30% 灰，深色模式下会消失） |
| 图形到标题间距 | 24–32pt |
| 标题 | 16–18sp / medium，行高 1.4，颜色 `on-surface` |
| 说明 | 13–14sp / regular，行高 1.5，颜色 `on-surface-variant`，宽度上限 280pt（避免长行） |
| 标题到说明间距 | 8pt |
| 说明到按钮间距 | 24pt |
| 主按钮 | 高度 40（Android）/ 44（iOS），宽度按内容 + 左右各 24pt 内边距 |
| 次级链接 | 主按钮下方 16pt，纯文字，颜色 `primary` |

## 文案写作的四条硬规则

1. **不要用「暂无」「尚未」「暂未」开头**。这类词在读起来像系统报错。
   直接说事实：「还没有项目」「今天的事都完成了」。
2. **不要用被动句和系统口吻**。「数据未被创建」→「还没有项目」。
3. **按钮用动词**。「确定」→「创建项目」；「好的」→「开启通知」。
4. **不用感叹号**。空状态里的感叹号会显得在硬撑情绪。

## 检查清单

- [ ] 五种空状态是否都有独立文案（不是复用一个组件传不同 title）
- [ ] 标题是否回答了「为什么是空的」
- [ ] 说明是否回答了「下一步做什么」（或说明为什么不需要做）
- [ ] 是否只有一个主按钮
- [ ] 搜索无结果时，标题里是否回显了搜索词
- [ ] 出错态是否按错误类型区分文案
- [ ] 未登录态是否说明了登录的好处，而不是命令式要求
- [ ] 深色模式下插画是否可见（不要用纯黑描边）
- [ ] 320pt 宽屏幕下说明文字是否在 3 行内
- [ ] 系统大字体（200%）下按钮文字是否溢出
