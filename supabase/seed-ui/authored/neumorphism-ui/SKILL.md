# 新拟态（Neumorphism / Soft UI）

新拟态用「一明一暗两个方向相反的阴影」把元素从同色背景里「挤」出来。
它的视觉假设是：**界面是一块被挤压成型的塑料**。
这个假设带来一个硬约束 —— 元素和背景必须同色 —— 也带来了它最致命的问题：
**同色就没有对比度**。

## 何时使用

- 做计算器、音乐播放器、智能家居面板这类「元件少、交互简单」的界面
- 落地页里一个孤立的 CTA 或开关，想要一点质感
- 已有界面想局部试新拟态，需要知道哪些位置绝对不能碰
- 用了新拟态但被无障碍审计打回，需要补救

## 核心规则

1. **元素背景色必须严格等于父容器背景色**，一个色值都不能差。
   这是新拟态的定义性约束。背景用 `#E0E0E0`、卡片用 `#E1E1E1`，
   阴影立刻就变成「贴在卡片上的两条脏线」，效果全毁。
   实现时用 CSS 变量共享同一个值，不要在两处各写一遍。

2. **双阴影的偏移、模糊、颜色三者必须成对。**

   ```css
   /* 基准背景 #E0E0E0 */
   --shadow-light: #FFFFFF;   /* 比背景亮 */
   --shadow-dark:  #BEBEBE;   /* 比背景暗 */

   box-shadow:
     8px 8px 16px var(--shadow-dark),    /* 右下：暗 */
     -8px -8px 16px var(--shadow-light); /* 左上：亮 */
   ```

   取值规则：
   - **偏移 4–12px**。小于 4px 看不出立体感，大于 12px 元素会「浮起来」变成普通投影
   - **模糊半径 ≈ 偏移 × 2**（8px 偏移配 16px 模糊）。模糊小于偏移会露出硬边，
     大于 3 倍会糊成一团
   - **偏移 ≤ 元素短边的 1/4**。40px 高的按钮最多用 10px 偏移
   - 光源方向**全站统一**，永远是左上（`-x -y` 亮、`+x +y` 暗），
     不要有的按钮左上来光、有的右上

3. **明暗两色与背景的亮度差要对称且足够。**
   以 `#E0E0E0`（相对亮度 0.745）为基准：
   - 亮色用 `#FFFFFF`（亮度 1.0，差 +0.255）
   - 暗色用 `#BEBEBE`（亮度 0.515，差 −0.230）
   两侧差值接近才自然。暗色如果只到 `#D0D0D0`（差 −0.09），立体感会非常弱。

4. **按下态用 inset 双阴影，不是缩小或变色。**

   ```css
   .btn:active {
     box-shadow:
       inset 6px 6px 12px var(--shadow-dark),
       inset -6px -6px 12px var(--shadow-light);
   }
   ```

   inset 的偏移和模糊**取外阴影的 0.7–0.8 倍**（8→6、16→12）。
   直接用同样的值会让凹陷看起来过深，像被戳穿了。

5. **新拟态本身无法满足 WCAG 1.4.11。** 这是数学问题，不是调参能解决的。
   `#E0E0E0` 背景上的元素，即使暗阴影加深到 `#A0A0A0`，对比度也只有 **2.0:1**；
   要达到非文本对比要求的 3:1，暗阴影需要到 `#767676` —— 那个颜色看起来是硬投影，
   已经和新拟态没关系了。
   **所以必须补第二重线索**：文字标签、图标、或 1px 描边。见下文「怎么做」。

6. **焦点态必须明显，且不能用新拟态表达。**
   键盘 Tab 到某个按钮时，`inset` 和外阴影的区别对色弱用户几乎不可见。
   焦点环要独立：`outline: 2px solid #1A73E8; outline-offset: 2px;`
   对比度 ≥ 3:1，且**不要**用 `outline: none` 去掉默认焦点。

7. **新拟态是单色的。** 一旦引入品牌色填充，元素和背景就不同色了，
   新拟态的前提消失。如果品牌色必须出现，只能用在**文字、图标、焦点环**上，
   不能用在容器的背景色上。

## 怎么做

### 1. 基础 token 层

```css
:root {
  --neu-bg:        #E0E0E0;
  --neu-light:     #FFFFFF;
  --neu-dark:      #BEBEBE;
  --neu-text:      #333333;   /* 与 #E0E0E0 对比度 9.6:1 */
  --neu-text-dim:  #5C5C5C;   /* 与 #E0E0E0 对比度 5.6:1，最小可用 */
  --neu-focus:     #1A73E8;
}

.neu-raised {
  background: var(--neu-bg);
  border-radius: 16px;
  box-shadow:
    8px 8px 16px var(--neu-dark),
    -8px -8px 16px var(--neu-light);
}

.neu-sunken {
  background: var(--neu-bg);
  border-radius: 16px;
  box-shadow:
    inset 6px 6px 12px var(--neu-dark),
    inset -6px -6px 12px var(--neu-light);
}
```

圆角取 12–20px。小于 8px 时阴影在角上会重叠成黑点，大于 24px 会显得软塌。

### 2. 补上「第二重线索」（这是能不能上线的分水岭）

新拟态元素必须至少带下列一项，否则用户无法判断它可点：

| 线索 | 做法 | 代价 |
| --- | --- | --- |
| 文字标签 | 按钮内直接写动词 | 最有效，几乎无代价 |
| 图标 | 24px 单色图标，对比度 ≥ 3:1 | 图标语义要准确 |
| 1px 描边 | `border: 1px solid rgba(0,0,0,.14)` | 轻微削弱新拟态质感 |
| 更深的外阴影 | 额外叠一层 `0 1px 2px rgba(0,0,0,.18)` | 立体感变「实」 |
| 颜色差异 | 元素背景比父容器亮 3–5% | 违反同色约束，谨慎 |

**推荐组合：文字标签 + 图标**。新拟态的按钮最好始终有文字，
纯图标的新拟态按钮在用户测试里点击率显著偏低。

### 3. 完整的按钮实现

```css
.neu-btn {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  gap: 8px;
  min-width: 120px;
  height: 48px;                 /* ≥ 44px 触摸目标 */
  padding: 0 24px;
  border: 0;
  border-radius: 16px;

  background: var(--neu-bg);
  color: var(--neu-text);
  font-size: 15px;
  font-weight: 600;
  letter-spacing: .02em;

  box-shadow:
    6px 6px 12px var(--neu-dark),
    -6px -6px 12px var(--neu-light);

  transition: box-shadow .15s ease;
  cursor: pointer;
}

/* hover 只把偏移加 1px，不要大改，否则会闪 */
.neu-btn:active,
.neu-btn[aria-pressed='true'] {
  box-shadow:
    inset 5px 5px 10px var(--neu-dark),
    inset -5px -5px 10px var(--neu-light);
}

.neu-btn:focus-visible {
  outline: 2px solid var(--neu-focus);
  outline-offset: 3px;
}

.neu-btn:disabled {
  /* 不能用 opacity，会破坏同色约束（且 opacity 会连文字一起淡） */
  box-shadow:
    inset 5px 5px 10px var(--neu-dark),
    inset -5px -5px 10px var(--neu-light);
  color: #9A9A9A;              /* 与 #E0E0E0 对比度 2.2:1，仅作"不可用"暗示 */
  cursor: not-allowed;
}
```

禁用态用「凹陷 + 低对比文字」。文字对比度可以低于 4.5:1，
因为 WCAG 对禁用控件有豁免，但**必须配合 `cursor: not-allowed` 和 `aria-disabled`**。

### 4. 开关（Toggle）

新拟态最适合的组件，因为开/关可以用「凸起 / 凹陷」天然表达：
轨道 `72×36` 用 `inset 4px 4px 8px` + `inset -4px -4px 8px`，
滑块 `28×28` 圆角 50% 用 `3px 3px 6px` + `-3px -3px 6px`，
`aria-checked='true'` 时 `translateX(36px)`。

关键：**开关的「开」状态必须靠位置区分，不能只靠阴影**。
再加上 `role="switch"` 和 `aria-checked`，屏幕阅读器才可用。

### 5. 深色主题下的新拟态

深色下基色换成 `--neu-bg: #2C2C2C`、`--neu-light: #383838`（不要用纯白）、
`--neu-dark: #1F1F1F`、`--neu-text: #E8E8E8`。
深色下的亮度差要**比浅色更大**，否则阴影在低亮度屏幕上完全看不见。
暗阴影不要用纯黑 `#000`，会形成硬边（原因见 `dark-mode-oled` 技能）。

### 6. 什么场景不要用

- **表单**：输入框需要明确的可编辑边界，新拟态的凹陷输入框在很多显示器上看不出边界
- **数据表格 / 后台**：信息密度高，新拟态的低对比会让扫描速度下降
- **面向老年用户或户外使用**：屏幕反光下阴影完全消失，界面变成一片灰
- **需要过 WCAG AA / 等保 / 政务规范的项目**：新拟态天然不满足 1.4.11
- **色彩丰富的品牌界面**：新拟态要求单色，和彩色品牌冲突
- **移动端低端机**：双阴影 + 大模糊半径在低端 GPU 上会有轻微掉帧，不如玻璃拟态严重但存在

### 7. 混合方案（推荐）

不要整站新拟态。做法：**主界面用常规设计，只在个别"元件"上局部使用**。

- 计算器的数字键盘 ✓
- 音乐播放器的播放/上一首/下一首 ✓
- 智能家居的灯光开关 ✓
- 整个设置页 ✗
- 整个登录表单 ✗

## 检查清单

- [ ] 元素背景色与父容器**完全相等**（用取色器逐像素验证）
- [ ] 全站光源方向统一（左上亮、右下暗）
- [ ] 偏移 4–12px，模糊 ≈ 偏移 × 2
- [ ] 偏移 ≤ 元素短边的 1/4
- [ ] 亮暗两色与背景的亮度差接近对称
- [ ] 每个可点元素都有文字标签或图标（不只有阴影）
- [ ] 按下态用 inset，且参数是外阴影的 0.7–0.8 倍
- [ ] 焦点环存在、对比度 ≥ 3:1、`outline-offset` ≥ 2px
- [ ] 触摸目标 ≥ 44×44px
- [ ] 禁用态用凹陷 + 低对比文字，不用 `opacity`
- [ ] 文字与背景对比度 ≥ 4.5:1
- [ ] 在亮度 50% 的显示器上（或手机户外）阴影仍可辨认
- [ ] 深色主题单独调过基色，不是把浅色值取反
- [ ] 用灰度模式（`filter: grayscale(1)`）看一遍，元素边界是否仍可分辨

## 常见错误

| 错误做法 | 为什么错 | 正确做法 |
| --- | --- | --- |
| 卡片背景 `#FFF`、父容器 `#F5F5F5` | 不同色，阴影变成脏线，效果全毁 | 用同一个 CSS 变量 |
| 偏移 2px 配模糊 20px | 阴影糊成一圈晕，看不出方向 | 模糊 ≈ 偏移 × 2 |
| 只用阴影不用文字/图标 | 用户无法判断是否可点，WCAG 1.4.11 不达标 | 补文字标签或 24px 图标 |
| 用 `opacity: .4` 做禁用态 | 破坏同色约束，且文字一起变淡 | inset 阴影 + 单独调文字色 |
| `outline: none` 去掉焦点环 | 键盘用户完全无法定位 | `:focus-visible` + 2px 实心 outline |
| 用 `:active` 只做 `scale(0.97)` | 缩放会让阴影偏移跟着变，边缘抖动 | 用 inset 双阴影 |
| 品牌色填进按钮背景 | 元素与背景不同色，新拟态前提消失 | 品牌色只用在文字/图标/焦点环 |
| 深色主题暗阴影用 `#000` | 纯黑形成硬边，且在 OLED 上有拖影 | 用比背景暗 8–10% 的灰 |
| 全站都用新拟态 | 表格、表单的可读性大幅下降 | 只在独立元件上局部使用 |
| 假设「用户能看出来是按钮」 | 明暗差只有 1.3:1，远低于 3:1 | 必须有第二重线索 |
