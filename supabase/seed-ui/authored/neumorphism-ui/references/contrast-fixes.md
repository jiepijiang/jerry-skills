# 新拟态的对比度问题与补救

## 一、先算清楚：新拟态到底差多少

WCAG 2.2 的 1.4.11「非文本对比度」要求：
**UI 组件的视觉边界、以及用于识别组件的状态指示，与相邻颜色的对比度 ≥ 3:1。**

对比度公式（相对亮度 L 已做 sRGB 线性化）：

```
contrast = (L_light + 0.05) / (L_dark + 0.05)
```

以最常见的 `#E0E0E0` 为背景（L = 0.745）：

| 元素色 | L | 与 #E0E0E0 的对比度 | 判定 |
| --- | --- | --- | --- |
| `#FFFFFF`（亮阴影） | 1.000 | 1.32:1 | 不达标 |
| `#F0F0F0` | 0.882 | 1.17:1 | 不达标 |
| `#D0D0D0` | 0.631 | 1.17:1 | 不达标 |
| `#BEBEBE`（典型暗阴影） | 0.515 | 1.41:1 | 不达标 |
| `#A0A0A0`（已经很重了） | 0.352 | 1.98:1 | 不达标 |
| `#8A8A8A` | 0.256 | 2.59:1 | 不达标 |
| `#767676` | 0.181 | **3.44:1** | 达标，但已经不像新拟态 |
| `#5C5C5C` | 0.107 | 5.06:1 | 达标，是硬投影 |

**结论**：要让元素边界自己达到 3:1，暗阴影必须深到 `#767676` 以下，
那时候它看起来就是一条硬投影，新拟态的特征（柔和、无边界）已经不存在了。

这不是「参数没调好」，是**风格定义和 WCAG 要求互斥**。
所以唯一的出路是**不依赖阴影来表达边界**，而是补第二重线索。

## 二、文字对比度是另一回事，可以达标

新拟态的元素**背景**对比度不够，但**元素上的文字**完全可以达标：

| 文字色 | 与 #E0E0E0 的对比度 | 用途 |
| --- | --- | --- |
| `#333333` | 9.6:1 | 正文、按钮标签 |
| `#4A4A4A` | 7.0:1 | 正文 |
| `#5C5C5C` | 5.1:1 | 次要文字（下限） |
| `#767676` | 3.4:1 | 仅大字（≥ 18.66px bold 或 ≥ 24px） |
| `#9A9A9A` | 2.1:1 | 仅禁用态（WCAG 对禁用控件有豁免） |

所以新拟态的**可读性**通常没问题，问题在**可发现性** ——
用户看不出哪里可以点。

## 三、补救方案（按性价比排序）

### 方案 1：文字标签（必做，成本最低）

按钮里写动词。这一条能解决大部分问题，因为它让「可点击」由文字语义承载，
而不是由阴影承载。

```html
<button class="neu-btn">保存草稿</button>
```

纯图标按钮必须配 `aria-label`，且图标本身与背景对比度 ≥ 3:1：

```html
<button class="neu-btn" aria-label="保存草稿">
  <svg aria-hidden="true" class="neu-btn__icon">…</svg>
</button>
```

```css
.neu-btn__icon { color: #4A4A4A; }   /* 与 #E0E0E0 对比度 7.0:1 */
```

### 方案 2：1px 描边（视觉代价最小）

```css
.neu-btn {
  border: 1px solid rgba(0, 0, 0, 0.16);   /* 与 #E0E0E0 合成后约 #BCBCBC，2.4:1 */
}
```

`rgba(0,0,0,0.16)` 叠在 `#E0E0E0` 上得到约 `#BCBCBC`，对比度约 2.4:1 ——
仍然不到 3:1。要达标需要 `rgba(0,0,0,0.42)` 左右（约 `#828282`），
但那条线会非常显眼。

**折中做法**：描边用 `rgba(0,0,0,0.16)` 做视觉修饰，
同时靠方案 1 的文字标签满足语义要求。审计时说明「组件边界由文字标签识别」，
这在 WCAG 的解释里是成立的（1.4.11 针对的是「识别组件所需」的对比度，
有文字标签时，阴影不是识别所必需的）。

### 方案 3：焦点环（必做，且必须够醒目）

```css
.neu-btn:focus-visible {
  outline: 2px solid #1A73E8;    /* 与 #E0E0E0 对比度 5.4:1 */
  outline-offset: 3px;
}
```

不要用 `box-shadow` 做焦点环 —— 新拟态元素本来就靠 box-shadow 表达状态，
用同一个属性表达焦点会冲突（`:active` 和 `:focus-visible` 同时命中时，
后写的规则会覆盖前一个）。用 `outline` 是唯一干净的做法。

### 方案 4：`prefers-contrast` 媒体查询

```css
@media (prefers-contrast: more) {
  .neu-btn {
    border: 1px solid #828282;
    box-shadow: 6px 6px 12px #9E9E9E, -6px -6px 12px #FFFFFF;
  }
  .neu-btn:active {
    box-shadow: inset 5px 5px 10px #9E9E9E, inset -5px -5px 10px #FFFFFF;
  }
}
```

在「更多对比度」模式下，把暗阴影加深、加描边。
这档模式下用户已经明确表示「我不在意美观，我要看得清」，
不要在这里坚持风格。

### 方案 5：`forced-colors`（Windows 高对比模式）

**在这个模式下，`box-shadow` 会被浏览器完全忽略**。
如果不做处理，新拟态界面会变成一片没有边界的纯色块，完全不可用。

```css
@media (forced-colors: active) {
  .neu-btn {
    border: 1px solid ButtonBorder;
    background: ButtonFace;
    color: ButtonText;
    box-shadow: none;
  }
  .neu-btn:focus-visible { outline: 2px solid Highlight; }
  .neu-btn:disabled { color: GrayText; border-color: GrayText; }
}
```

可用系统色关键字：`Canvas` / `CanvasText` / `ButtonFace` / `ButtonText` /
`ButtonBorder` / `Highlight` / `HighlightText` / `LinkText` / `GrayText` /
`Field` / `FieldText` / `Mark`。

这是**最容易被忽略、后果最严重**的一档：不做处理时界面等于坏了，
而不只是「不好看」。

### 方案 6：状态不靠阴影单独表达

选中 / 未选中、开 / 关这类状态，阴影（凸起 / 凹陷）只能作为**辅助**，
必须有第二个通道：

| 状态 | 第二通道 |
| --- | --- |
| 选中 | 文字加粗 + 颜色变深，或左侧 4px 指示条 |
| 开关「开」 | 滑块位置 + 可选的颜色变化 |
| 禁用 | `aria-disabled="true"` + `cursor: not-allowed` + 文字色降到 `#9A9A9A` |
| 加载中 | 元素内显示 spinner，而不是只把阴影变成凹陷 |

### 方案 7：提供一个「高对比主题」开关

如果产品受众包含低视力用户，最彻底的做法是在设置里给一个显式开关，
切换到一个完全非新拟态的主题（白底 + 边框 + 实心按钮）。
这比调阴影参数有效得多，也让审计有据可依。

## 四、审计前的自查清单

- [ ] 把页面截图转成灰度，元素边界是否仍可分辨
- [ ] 用 `filter: grayscale(1) contrast(0.5)` 模拟低对比屏，边界是否消失
- [ ] 键盘 Tab 走一遍，每一步是否都能看出焦点在哪
- [ ] Windows 高对比模式下打开，界面是否仍有边界（`forced-colors` 处理）
- [ ] 系统「减少动画」下过渡是否已关闭
- [ ] 亮度 50% + 户外强光模拟下，按钮是否还能找到
- [ ] 每个可点元素是否都有文字标签或 `aria-label`
- [ ] 用 axe DevTools / Lighthouse 跑无障碍审计，`color-contrast` 与
      `target-size` 两条是否通过（`target-size` 要求 24×24 CSS px 最小，
      新拟态按钮建议做到 44×44）

## 五、一句话总结

新拟态**不可能**靠自身满足 WCAG 1.4.11。
要么接受「用文字标签 + 焦点环 + forced-colors 兜底」这套组合，
要么就不要在有合规要求的项目里用它。
最差的做法是：用了新拟态，又没做任何补救，然后指望审计放过。
