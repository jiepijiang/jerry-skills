# 激活漏斗与新手引导

SaaS 的核心矛盾：**注册很容易，但用户不会自己走到「啊哈时刻」**。
激活漏斗的工作是把用户从注册推到那个时刻，且尽量不用遮罩式引导。

## 一、先定义「激活」

激活 ≠ 注册，也 ≠ 登录。它是一个**用户第一次获得价值的动作**。

好的激活事件要满足三条：

1. **可观测**：服务端能埋点，不依赖用户主观感受
2. **与留存强相关**：做过这件事的用户，次月留存明显更高
3. **用户能理解**：能写成一句用户看得懂的话

| 产品类型 | 差的激活事件 | 好的激活事件 |
| --- | --- | --- |
| 项目管理 | 注册完成 | 创建项目并添加第 1 个任务 |
| 数据分析 | 登录后台 | 接入 1 个数据源并看到第一张图 |
| 协作工具 | 完善资料 | 邀请第 1 位同事并完成 1 次评论 |
| API 服务 | 生成 Key | 用 Key 成功发出第 1 次请求 |

## 二、把激活拆成 3–5 步

步骤太多用户会放弃。3–5 步是经验区间。

```
1. 创建第一个项目        （30 秒内可完成）
2. 邀请至少 1 位同事      （决定产品能否形成网络效应）
3. 接入数据源 / 导入数据   （最难的一步，需要最多帮助）
4. 发布 / 分享第一个成果   （价值外化，产生回访动机）
```

**第 1 步必须能在 60 秒内完成**。如果第一步就要填 15 个字段，
大部分用户会在这一步流失。把必要信息压到最少，其余延后补全。

## 三、界面上的落点

### 1. 首页 checklist 卡片

- 位置：首页最上方，标题下方
- 显示：进度条 + `已完成 N / M 步` + 每步一行
- 未完成项：可点击，直接跳到执行位置
- 已完成项：打勾 + 灰色删除线，**不可点击**
- 全部完成后：**自动隐藏**（服务端下次渲染不再输出）
- 允许用户手动折叠，折叠状态存 localStorage

### 2. 空态引导

每个空列表页都是天然的引导位置：

```html
<div class="empty">
  <h3>还没有项目</h3>
  <p>项目用来组织任务、成员和文件。创建一个项目就能开始协作。</p>
  <button class="btn btn--primary">创建第一个项目</button>
  <a href="/templates">或从模板开始 →</a>
</div>
```

空态三段式：**这是什么 → 为什么需要 → 怎么做**。
「暂无数据」四个字是完全不合格的空态。

### 3. 上下文提示（in-context hint）

代替全屏遮罩式 tour，在用户**真正到达那个界面时**给一次性提示：

```html
<div class="hint" role="status">
  拖动卡片可以调整顺序 <button aria-label="知道了">知道了</button>
</div>
```

- 只在该功能首次出现时展示一次，展示过就写标记
- 用 `role="status"` 让读屏用户也能感知
- 不阻断操作（不是 modal），可以忽略
- 提示文案 ≤ 20 字，且必须描述**一个具体动作**

### 4. 为什么不用全屏遮罩式 tour

| 问题 | 后果 |
| --- | --- |
| 用户记不住 5 个步骤的蒙层 | 关掉后完全不记得，等于没做 |
| 遮罩阻断真实操作 | 用户想直接试，被迫先点 5 次「下一步」 |
| 与真实界面脱节 | 提示的是理想路径，用户真实数据下界面不同 |
| 跳过按钮太显眼 | 多数用户直接跳过 |

如果一定要用 tour，限制在 **≤ 3 步**，且每一步都要能直接操作真实界面。

## 四、摩擦点的处理

| 摩擦 | 处理 |
| --- | --- |
| 注册要填太多 | 只要邮箱 + 密码，公司名/角色延后到首次使用时问 |
| 要验证邮箱才能用 | 允许先进入产品，在「需要通知/协作」时才强制验证 |
| 导入数据复杂 | 提供 3 种方式：手动录入、CSV 上传、从竞品一键迁移 |
| CSV 字段映射难 | 自动匹配表头，匹配不上的高亮让用户手动指定，并提供预览前 5 行 |
| 团队邀请没人响应 | 提供可复制的邀请链接，不依赖邮件送达 |
| 不知道该填什么 | 每个输入框给真实示例值（`如：产品周会`），不用 placeholder 当标签 |

## 五、埋点

激活漏斗的每一步都要埋三个事件：

| 事件 | 用途 |
| --- | --- |
| `step_viewed` | 看到该步骤（分母） |
| `step_started` | 开始执行（暴露「开始后就放弃」的步骤） |
| `step_completed` | 完成 |

有了这三个，才能算出每一步的真实流失率。
只埋「完成」事件，无法区分「没看到」和「看到了但放弃」。

必埋的额外事件：

- `onboarding_collapsed` / `onboarding_dismissed`：判断清单是否扰民
- `empty_state_cta_clicked`：判断空态引导是否有效
- `hint_dismissed`：判断上下文提示是否被普遍忽略

## 六、常见反模式

| 反模式 | 症状 | 修法 |
| --- | --- | --- |
| 把注册当激活 | 注册量好看但留存极差 | 重新定义激活事件为「首次获得价值」 |
| 激活步骤 8 步 | 完成率断崖式下降 | 砍到 3–5 步，其余延后 |
| 第一步就要填 15 个字段 | 60 秒完不成，用户流失 | 只留必填 2–3 项 |
| 全屏遮罩 tour | 用户直接跳过，记不住任何内容 | 改 checklist + 空态引导 |
| 空态只写「暂无数据」 | 用户卡住，不知道下一步 | 三段式空态 + 主按钮 |
| 引导清单完成后常驻 | 长期用户首屏被占用 | 完成即隐藏 |
| 只埋完成事件 | 无法定位流失在哪一步 | 每步埋 viewed / started / completed |
| 强制邮箱验证才能进入 | 首日流失显著上升 | 延后到真正需要时再验证 |
