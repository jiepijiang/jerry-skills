# 多租户、角色权限与审计日志

企业客户在采购 SaaS 时，会问三类问题：
「我的数据会不会和别人混在一起」「谁能看到我的数据」「出问题能不能追溯」。
这一节讲怎么用界面回答它们。

## 一、租户层级模型

常见的三层结构：

```
组织 Organization（租户，计费与合同主体）
 └── 工作区 Workspace（业务隔离，成员与权限的边界）
      └── 项目 Project / 资源 Resource
```

两层结构（组织 → 项目）也常见，取决于产品复杂度。
**关键**：权限边界必须落在一个明确的层级上，不能既按组织又按工作区授权，
否则用户永远说不清「我这个权限是在哪一级给的」。

## 二、工作区切换的界面规范

### 位置与尺寸

- 固定在顶栏最左，与 Logo 相邻或替代 Logo 位置
- 宽度自适应但最大 240px，名称超 16 汉字省略
- 高度 32–36px，热区整块可点（含内边距）

### 下拉内容

```
┌─────────────────────────────┐
│ 云雀科技          管理员     │  ← 当前，有勾选标记
│ 北辰数据          编辑者     │
│ 个人空间          所有者     │
├─────────────────────────────┤
│ 查看全部工作区              │
│ + 新建工作区                │
└─────────────────────────────┘
```

- 最多显示 5 个最近使用
- 每项显示角色，让用户知道切过去能做什么
- 搜索：工作区 > 10 个时，下拉顶部出现搜索框

### 切换时的行为

1. 立即展示全屏 loading（覆盖内容区，保留顶栏和侧栏）
2. 清空所有缓存的数据（列表、详情、筛选状态）
3. 更新 URL 中的 workspace 标识
4. 重新拉取侧栏可见的菜单（权限可能不同）
5. loading 结束后滚动到页面顶部

**不能做的**：只替换标题、只替换数据但不重置筛选条件、
切换后仍显示上一个工作区的 toast 消息。

## 三、角色模型

推荐的四角色模型（够用且好理解）：

| 角色 | 典型权限 | 适用 |
| --- | --- | --- |
| 所有者 Owner | 全部，含转让与删除工作区 | 每个工作区恰好 1 人 |
| 管理员 Admin | 成员管理、计费、所有内容操作 | 1–3 人 |
| 编辑者 Editor | 内容增删改，不能改成员与计费 | 大多数成员 |
| 只读 Viewer | 仅查看与导出 | 外部合作方、审计 |

规则：

- **所有者唯一**，转让是独立操作（要求二次确认 + 输入工作区名）
- 角色数量 ≤ 5。超过 5 个自定义角色，用户无法理解差异
- 如果确实需要细粒度权限，用「基础角色 + 可选附加权限」两层，
  不要做成 20 个角色的矩阵

## 四、界面上的权限表达

### 成员列表

```html
<tr>
  <td class="member">
    <img src="…" alt="" width="32" height="32">
    <div><strong>李维</strong><small>li@yunque.com</small></div>
  </td>
  <td>
    <button class="role role--admin" aria-haspopup="dialog">管理员</button>
  </td>
  <td>2 小时前</td>
  <td><button aria-label="更多操作">···</button></td>
</tr>
```

- 角色 chip 可点击，弹出**该角色能做什么**的清单（3–5 条具体描述）
- 修改角色时给出**影响提示**：`改为只读后，该成员将无法编辑 12 个已有项目`
- 移除成员时说明**其创建的内容如何处理**（保留 / 转移给某人）

### 权限不足的状态

三种处理，按场景选：

| 场景 | 处理 |
| --- | --- |
| 菜单项整个不可用 | 隐藏该菜单项（最干净） |
| 页面可见但不能操作 | 按钮置灰 + tooltip 说明所需角色 |
| 通过链接直接访问 | 显示说明页 + `联系管理员`（可复制邮箱） |

**不要**让用户点进去再弹一个「403 无权限」的空白页。

## 五、审计日志

### 必须记录的操作

- 成员与权限：邀请、移除、改角色、转让所有权
- 数据：删除、批量导出、批量修改
- 计费：订阅变更、支付方式变更、发票下载
- 安全：密码修改、两步验证开关、SSO 配置、API Key 创建与吊销
- 集成：Webhook 增删、第三方授权

### 界面规范

```
时间                 操作人          操作                           IP            结果
2026-10-12 14:32:08  李维 li@…       删除了项目「A 测试」            10.2.3.4      成功
2026-10-12 14:28:51  王倩 wang@…     将 李维 的角色改为 只读          10.2.3.9      成功
2026-10-12 14:20:03  李维 li@…       导出成员列表（CSV，312 行）      10.2.3.4      成功
2026-10-12 13:55:12  匿名            尝试登录（密码错误）            203.0.113.7   失败
```

- 时间：`YYYY-MM-DD HH:mm:ss`，显示本地时区，并在页面注明时区
- 操作：**动宾结构 + 对象名**，写「删除了项目「A 测试」」而非「删除项目」
- IP：等宽字体，完整显示（不要脱敏，这是审计需要）
- 结果：成功 / 失败；失败要给出原因类别
- 筛选：时间范围（今天/7 天/30 天/自定义）、操作人、操作类型、结果
- 导出：CSV，导出动作本身也要被记录
- 保留：至少 90 天；企业版通常要求 1 年，界面要能查到保留策略

### 不可变性

- 日志**不可编辑、不可删除**，界面上不提供删除入口
- 导出为 CSV 后，文件内容与界面一致（不要导出时做二次脱敏，除非明确标注）

## 六、SSO 与安全设置的界面

即使未开通，也要在安全设置里显式列出：

```
单点登录（SSO）
  支持 SAML 2.0 / OIDC / SCIM 自动同步
  状态：未开通        [了解详情]  [联系我们开通]
```

企业采购者会拿这个清单来核对需求。**不显示 = 认为你没有**。

会话管理：

- 列出所有活跃会话：`设备 / 浏览器 / 位置 / 最近活跃 / IP`
- 每个会话可单独登出
- 提供「登出所有其他设备」

## 七、数据位置与合规

设置页（或安全页）给出：

- 数据存储区域（如 `中国大陆（杭州）`）
- 备份频率与保留期（`每日备份，保留 30 天`）
- 数据导出与删除入口（`导出全部数据` / `删除工作区及全部数据`）
- 合规认证列表（如有：等保、ISO 27001），**只列真实拥有的**

## 八、常见反模式

| 反模式 | 症状 | 修法 |
| --- | --- | --- |
| 权限既按组织又按工作区 | 用户说不清自己在哪一级被授权 | 权限只落在一个层级 |
| 工作区切换不重置筛选 | A 组织的筛选条件带到 B 组织，看到错误数据 | 切换时清空所有本地筛选状态 |
| 自定义角色 15 个 | 管理员无法理解差异，实际只用前 3 个 | 限制 ≤ 5 个角色 |
| 无权限项点击后弹 403 | 用户以为系统故障 | 隐藏，或置灰并说明所需角色 |
| 审计日志可删除 | 失去审计价值，合规不通过 | 只读、不可删 |
| 日志只写「删除项目」 | 不知道删的是哪个项目，无法追溯 | 动宾 + 对象名 |
| 不显示 SSO 支持情况 | 企业采购者判定为不支持，直接出局 | 未开通也列出并给开通路径 |
| 会话列表只显示设备名 | 无法判断哪一个是异常会话 | 补位置、IP、最近活跃 |
| 列出未拥有的合规认证 | 严重的合规与法律风险 | 只列真实持有的认证 |
