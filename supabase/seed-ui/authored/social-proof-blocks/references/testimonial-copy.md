# 证言文案的筛选、改写与授权

证言的质量**在采集阶段就已经决定**，设计只能放大或缩小它。
这一节讲怎么从真实素材里筛出能用的证言，以及改写时的边界。

## 一、什么样的原始证言能改造成好证言

采集时优先索取带以下要素的评价：

1. **前后对比数字**：`转化率从 3.1% 到 5.4%`、`周报从 3 小时到 20 分钟`
2. **具体场景**：`双十一当天 8 万订单`、`跨 3 个时区协作`
3. **替代方案**：`之前用 Excel + 微信，经常对不上版本`
4. **决策理由**：`选它是因为不用改我们的现有流程`

**不要**收「很好用」「服务不错」「推荐」这类无锚点评价 —— 采集时就追问：
`具体是哪个环节变好了？大概省了多少时间？`

## 二、改写规则（合规边界）

允许的改写：
- 修正错别字、口语化冗余（`那个，就是说` → 删除）
- 合并同一段评价里的重复表达
- 在**不改变事实**的前提下调整语序，让开头先出现结论

不允许的改写：
- 添加客户没提过的数字
- 把「某功能挺好的」放大成「这个产品改变了我们的工作方式」
- 拼接两段不同语境的评价
- 代写后让客户「确认一下」—— 客户往往不会细看，风险由你承担

**必须**：发布前把最终文案（含头像、职位、公司名）发给客户书面确认。
口头同意不算，截图同意要留档。

## 三、长度与结构

理想长度 **40–120 字**（中文）。超过 120 字的证言基本没人读完，
少于 40 字显得敷衍。

推荐结构（三段，可不全用）：

```
[问题/背景] 20 字以内
[具体做法或对比] 30–60 字
[结果数字] 20 字以内
```

示例：

> 接入前新客注册转化卡在 3.1%，主要是表单太长。换成渐进式表单后
> 两周内跑到 5.4%，我们没有改任何投放。

- 背景：`转化卡在 3.1%`
- 做法：`换成渐进式表单`
- 结果：`两周内跑到 5.4%`

三条齐全，且有一个可验证的数字。

## 四、多条证言的多样性检查

把 3–6 条证言放在一起时，做一次「雷同度」自查：

| 维度 | 要求 |
| --- | --- |
| 长度 | 至少 3 种不同长度（短 40 / 中 70 / 长 110） |
| 行业 | 尽量覆盖不同行业，不要全是同一行业 |
| 角色 | 覆盖不同角色（技术、业务、管理者） |
| 角度 | 有的讲效率、有的讲成本、有的讲稳定性 |
| 句式 | 不要都以「我们」「这个产品」开头 |

如果 5 条证言都在讲「省时间」，用户会认为产品只有这一个卖点。

## 五、评分展示

如果展示评分，**要展示分布**而不是单一平均分：

```
4.8 / 5
5★ ████████████████ 78%
4★ ████ 15%
3★ ██ 5%
2★ █ 1%
1★ █ 1%
```

全是 5 分的评分（4.9 或 5.0）反而降低可信度 ——
真实产品的评分分布一定是有尾巴的。

如果只有 2–3 条评价，**不要做评分**，直接展示原文即可。
样本量太小做百分比会显得刻意。

## 六、匿名与脱敏

当客户不允许披露公司名时：

- 用「某头部电商平台 · 技术负责人」这类**有信息量的匿名**，
  而不是「王先生」
- 头像用姓名首字母色块，不要用图库头像（会更假）
- 成果数字可以保留（这通常不是敏感信息），但去掉具体业务指标名

**底线**：宁可少放一条证言，也不要为了填满三列而编造。
三列布局只有 2 条真证言时，改成两列居中，或加一张数据背书卡补位。

## 七、来源标注

每条证言下方可选加来源，提升可查证性：

- `来自 G2 2026 年冬季报告`
- `来自客户回访（2026-08）`
- `来自 App Store 用户评价`

有来源的证言比没有的转化高，但**来源必须真实可点**。
写一个打不开的链接，比不写更糟。
