# 微信里做不了什么 · 能力清单与真机调试

写需求前先对照这份清单。里面任何一条「做不了」的事项，
如果被写进需求文档，最后的实现一定是绕过方案，而且体验会打折。

## 一、能力黑名单

| 想做的事 | 能否实现 | 说明与替代 |
| --- | --- | --- |
| 代码自动弹出分享面板 | ❌ | 只能预设内容，用户必须点右上角 |
| 跳转到外部 App（scheme / 应用宝） | ❌（白名单除外） | 微信 7.0.9 后基本屏蔽，只能引导「在浏览器打开」 |
| `window.open` 打开新窗口 | ⚠️ 部分 | 多数机型被拦截或在同一 WebView 内打开；用 `location.href` |
| 获取用户手机号 | ❌ | 需小程序 `getPhoneNumber` |
| 自动播放带声音的音频/视频 | ❌ | 必须用户手势触发 |
| 视频内联播放（不强制全屏） | ⚠️ | 需 `playsinline` + `webkit-playsinline` + `x5-playsinline`，老 Android 仍会全屏 |
| 调用摄像头 / 麦克风（`getUserMedia`） | ❌ | 微信内被禁用，需小程序或原生 |
| Web Bluetooth / NFC / 串口 | ❌ | 完全不支持 |
| 后台持续播放音频（iOS） | ❌ | 切后台即暂停 |
| 静默获取精确定位 | ❌ | 需 JSSDK `getLocation` + 后台权限，且会弹提示 |
| 下载并保存任意文件（iOS） | ❌ | iOS 无文件系统；可引导用户「用其他应用打开」 |
| 长按识别任意二维码 | ⚠️ | 只有 `<img>` 且尺寸足够时才可识别；canvas 绘制的不行 |
| 修改微信右上角菜单（隐藏「复制链接」等） | ❌ | 只能追加，不能隐藏系统项 |
| 让页面「永远不被清理」 | ❌ | 微信会回收 WebView，长时间放置后回到页面会重新加载 |
| 使用 `alert` / `confirm` 弹窗 | ⚠️ | 微信内 `alert` 可用但样式不可控；`confirm` 部分版本被拦，建议自绘 |
| 精确获取 `window.innerHeight` | ⚠️ | 微信工具栏收起/展开会变化，用 `visualViewport` |

## 二、容易忽略的行为差异

### 1. 存储会被清理

iOS 的 WKWebView 在系统存储紧张时可能清空 `localStorage`、`sessionStorage`、
`IndexedDB`。用户清理微信缓存、微信版本升级也会清空。

对策：
- 登录态放 cookie（`Secure; SameSite=Lax`）或服务端 session。
- 表单草稿同时上报服务端（至少每 30s 或失焦时）。
- 用户偏好（主题、密度）丢失是可接受的，不要用本地存储做关键业务状态。

### 2. 页面会重新加载

微信回收 WebView 后，用户从聊天列表点回来会重新执行整个页面。
任何「只靠 JS 内存保存的状态」都会丢。

对策：状态尽量编码进 URL（`?step=2&id=123`），或存服务端。

### 3. 返回行为不可控

- 微信左上角返回、Android 物理返回键都触发 `history.back()`。
- 栈空时直接退出 WebView 回聊天窗口，**没有二次确认的机会**。
- 想拦截返回只能在 `popstate` 里 `pushState` 推回去，但用户会感觉「返回失效」，
  必须配二次确认弹窗才放行，否则用户被困。

### 4. 长按行为被微信接管

长按图片会弹「发送给朋友 / 保存图片 / 识别二维码」；
长按文字会弹「复制 / 搜一搜」。
页面自己的长按菜单会被系统菜单盖住。

对策：需要自定义长按交互时，元素上设 `-webkit-touch-callout: none` 并避免用 `<img>`。

### 5. 微信会注入自己的样式

微信 iOS 会给 `<a>`、`<img>` 等元素注入默认样式与行为（例如 `img` 可长按保存）。
如果页面样式被莫名影响，先排查是否是微信注入。

```css
/* 关掉微信对图片的长按菜单 */
img { -webkit-touch-callout: none; pointer-events: none; }
/* 需要点击的图片用外层容器接管事件 */
```

### 6. 字体大小设置会影响页面

微信「设置 → 通用 → 字体大小」会改变 WebView 默认字号。
用 `rem` 且根字号基于 `vw` 的页面，在小/大字体档位下会显示异常。

对策：
```css
body { -webkit-text-size-adjust: 100%; }
```
并把关键文字用 px 定死。

### 7. 微信分享链接会带参数

用户从聊天里点开的链接会带上 `from=singlemessage` / `from=groupmessage` /
`from=timeline` / `isappinstalled=0` 等参数。
统计分享来源可以用这些参数，但**不要把它们写进业务判断**。

## 三、真机调试通道

### iOS 微信（推荐，信息最全）

1. iPhone：设置 → Safari → 高级 → 打开「网页检查器」。
2. 用数据线连 Mac。
3. Mac Safari：开发 → 你的 iPhone → 选择对应的微信页面。
4. 可以看 Console、Network、Elements，与桌面调试一致。

注意：微信 iOS 的 WKWebView 在 Safari 里显示为「微信」下的页面列表。
如果列表是空的，检查是否信任了这台电脑。

### Android 微信

1. 手机开启「开发者选项 → USB 调试」。
2. 微信内：我 → 设置 → 帮助与反馈 → 右上角扳手 → 打开「X5 调试」（或「XWeb 调试」）。
3. Chrome 打开 `chrome://inspect/#devices`，找到对应页面点 `inspect`。
4. 若列表为空，用 `chrome://inspect` 的「Configure」加上 `localhost:9222` 并确认驱动已装。

XWeb 内核版本查询：微信内打开 `https://debugxweb.qq.com/?inspector=true`，
可以看内核版本与调试开关。

### 通用：vConsole

```js
if (import.meta.env.DEV) {
  const { default: VConsole } = await import('vconsole')
  new VConsole()
}
```

优点：不需要数据线，任何手机都能看 console 和 network。
缺点：看不到 DOM 与 CSS，且和微信自己的注入脚本可能互相干扰。

### 微信开发者工具的「公众号网页」

可以输入 URL 调试，但**它不是真实微信内核**，JS-SDK 的签名、
XWeb 的行为、视频播放策略都无法验证。
只能用于快速看布局，不能作为验收依据。

## 四、真机验收清单

- [ ] iOS 微信：分享到朋友，标题/描述/缩略图正确
- [ ] iOS 微信：分享到朋友圈，标题/缩略图正确
- [ ] Android 微信：同上两项
- [ ] 从聊天窗口点开链接，能正常进入并带上 `from` 参数
- [ ] 授权流程无循环，`code` 未被重复使用
- [ ] 支付完成/取消/失败三条路径都有正确落点
- [ ] 微信左上角返回不会导致白屏或状态错乱
- [ ] 切到其他聊天再切回来，页面状态可恢复（或被优雅重置）
- [ ] 微信字体大小调到大档，布局不破
- [ ] 长按图片/文字的行为符合预期（没有被系统菜单意外覆盖关键交互）
- [ ] 视频在 iOS 与 Android 微信下都能按预期播放
- [ ] 弱网下（微信内限速）首屏 3s 内有内容
- [ ] 微信版本差异：在近两年内的 2–3 个版本上各测一遍
